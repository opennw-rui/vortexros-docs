# 性能参考

硬件选型需要同时考虑CPU、网卡、接口驱动、报文长度、封装层数和实际业务功能。基本IPv4转发、ACL、加密隧道和VXLAN的处理成本不同，不能用单项转发速率代表所有业务。

FD.io CSIT提供公开的VPP性能结果，可按CPU、网卡、驱动和用例筛选：

- [CSIT测试数据](https://csit.fd.io/report/)
- [CSIT 26.10报告](https://csit.fd.io/cdocs/release_notes/current/#csit-2610-selected-performance-comparisons)
- [测试台规格](https://csit.fd.io/cdocs/infrastructure/fdio_dc_testbed_specifications/)

使用这些数据时，应核对版本、帧长、worker数量、驱动、功能组合和丢包标准。上游结果仅适用于其注明的条件，不是VortexROS或自有插件的设备吞吐保证。

可使用的CPU和网卡路径见[支持的硬件](../installation/hardware.md)。VortexROS当前不提供按CPU或网卡型号承诺的统一吞吐数值。


## VLAN 交换

以下为 0.29-dev-debug1 的 Native VLAN 路径与同基线的原生 26.10 路径的固定速率对照。采用 memif 双队列、128 字节帧（不含 FCS）、32 条流和固定 CPU；单、双 worker 各独立运行 3 次，每次 10 秒，目标 1.0 Mpps。每轮交错运行新旧实现，第二轮调换先后顺序。

带标签对照使用原生 dot1q 子接口和 POP/PUSH；无标签对照使用原生父接口直桥。后者没有 PVID 服务映射及服务子接口接收计数，功能范围不同，因此不能把它直接视为相同功能的零成本基准。

| 输入 | worker 数 | 原生 clocks/packet，3 次 | 新版 clocks/packet，3 次 | 原生均值 | 新版均值 | 均值变化 |
|---|---:|---|---|---:|---:|---:|
| 带标签 | 1 | 353.60 / 362.80 / 340.50 | 353.50 / 340.90 / 373.00 | 352.30 | 355.80 | +0.99% |
| 带标签 | 2 | 393.50 / 391.15 / 402.40 | 397.30 / 392.05 / 387.70 | 395.68 | 392.35 | −0.84% |
| 无标签 | 1 | 227.70 / 239.40 / 234.80 | 264.40 / 283.10 / 264.70 | 233.97 | 270.73 | +15.71% |
| 无标签 | 2 | 277.65 / 274.25 / 269.95 | 290.35 / 296.95 / 293.25 | 273.95 | 293.52 | +7.14% |

24 次样本累计产生 240,089,539 个报文，发送端、被测端收发及接收端计数全部相等，接收字节数与帧长一致。双 worker 各处理约一半报文。新版无标签报文复用已有无标签快速分类，避免标签解析和空标签改写；带标签报文继续使用原生子接口查找和已有 L2 标签改写节点，没有新增图节点。

另对优化前 Native VLAN 运行库补测了无标签业务，使用相同固定速率、帧长、队列和 CPU 布局，每种 worker 数运行 3 次。下面是分时对照，未与新版逐次交错，不能据此排除宿主负载变化的影响：

| worker 数 | 优化前 clocks/packet，3 次 | 优化前均值 | 优化后均值 | 均值变化 |
|---:|---|---:|---:|---:|
| 1 | 324.40 / 357.20 / 323.30 | 334.97 | 270.73 | −19.18% |
| 2 | 396.80 / 372.25 / 377.20 | 382.08 | 293.52 | −23.18% |

这里累计 Ethernet 输入及 L2 输入、标签改写、学习、查表、输出六个节点的每包时钟。VPP 轮询 worker 的整体 CPU 占用在新旧版均接近 100%，不能直接据此计算节省的 CPU 百分比。带标签路径在本组测试中接近原生；无标签仍有 PVID 服务映射及计数成本，不宣称整体零开销。

这些数值不是吞吐上限。三次结果仍有波动，虚拟化宿主的物理 CPU 布局未独立确认；不能据此宣称统计等价，也不能外推为物理网卡线速保证。功能配置和生效条件见 [VLAN](../operator/vlan.md)。

## 单接口收包路径的 PVID 开销

另使用 VPP 自带 Packet Generator 固定每批 256 包，隔离收包批量变化对节点计时的影响。输入帧长 128 字节，每种配置测量 3 次；单、双 worker 分别绑核，双 worker 按各自处理包数加权。以下只统计 ethernet-input 节点，不是整个转发链或网卡吞吐。

| 路径 | 1 worker，cycles/packet | 2 workers，cycles/packet |
|---|---:|---:|
| 旧 PVID 路径 | 48.00 | 47.91 |
| 优化后 PVID 路径 | 22.67 | 22.32 |
| 原生 dot1q 子接口 | 29.67 | 29.90 |
| 无标签父接口直桥 | 11.67 | 未测 |

PVID 新旧实现逐轮交错；双 worker 的 dot1q 对照也在同一轮交错，单 worker 的 dot1q 单独运行三次。dot1q 与 PVID 使用相同构建中的原生子接口机制及同一输入长度；dot1q 输入去掉 4 字节标签，因此接收端字节数分别按实际输出长度核对。所有样本均核对产生量、业务接口接收包数与字节数、输出包数。直桥未执行 PVID 服务映射和业务子接口统计，只作为较低成本参考。

优化后，无标签业务不再进入标签慢分类，也不再先推进、再回退以太网头；仍保留 VLAN 准入、端口状态判断、业务接口统计和控制报文处理。带标签报文继续通过原有子接口分类。该节点的 PVID 开销降低约 53%，不代表整机 CPU 降低 53%，也不保证所有驱动、批量和业务组合达到同样收益。

使用 DPDK testpmd 的 memif IO 转发模式另测带标签与无标签业务，按 1.0 Mpps 交错各运行三次，累计 12,020,928 包均完成转发。该模式不执行 VLAN 准入或 PVID 映射；测到的 busy cycles/packet 分别为无标签 482.56 / 470.35 / 417.84、带标签 446.06 / 485.79 / 482.09，波动区间重叠，不能将差值解释为稳定的 VLAN 成本，也不能与上表的单节点时钟直接相比。

VPP 轮询负载和批量计时的解释见 [VPP CPU 使用说明](https://docs.fd.io/vpp/23.02/gettingstarted/troubleshooting/cpuusage.html)；DPDK IO 模式与时钟记录语义见 [testpmd 说明](https://doc.dpdk.org/guides-24.07/testpmd_app_ug/testpmd_funcs.html)。

## memif 整链路固定速率对照

在相同运行库中，对比无标签PVID服务与原生dot1q子接口，二者均保留VLAN准入及业务子接口收发统计。采用三节点memif拓扑、128字节输入及输出、32条流、双队列、4096项环；分别使用默认零拷贝和显式复制接收。每种组合在1.0 Mpps下运行三次，每次8秒，逐轮调换实现及模式的先后顺序。

下表累计被测节点从Ethernet分类到memif发出的全部active处理节点：Ethernet、L2输入及标签改写、学习、查表、L2输出、接口输出、memif TX。双worker按实际处理包数加权。接收轮询另列在原始记录中，因为其计时包含空轮询，不能当成纯报文处理成本。单位为VPP packet-clocks/packet。

| memif接收 | worker数 | PVID三次 | 原生dot1q三次 | PVID均值 | dot1q均值 | 均值变化 |
|---|---:|---|---|---:|---:|---:|
| 零拷贝 | 1 | 485.40 / 380.20 / 402.90 | 655.70 / 557.20 / 541.20 | 422.83 | 584.70 | −27.68% |
| 零拷贝 | 2 | 519.50 / 589.90 / 521.35 | 714.85 / 733.10 / 640.20 | 543.58 | 696.05 | −21.90% |
| 复制 | 1 | 476.20 / 396.00 / 373.50 | 543.50 / 472.30 / 426.30 | 415.23 | 480.70 | −13.62% |
| 复制 | 2 | 581.65 / 636.90 / 485.65 | 641.65 / 561.50 / 514.55 | 568.07 | 572.57 | −0.79% |

24个有效样本累计192,086,353包，产生量、发送端TX、被测端RX/TX、接收端RX全部一致；两端业务子接口包数与字节数也严格一致。双worker各处理约一半流量。PVID输入及输出均无标签，dot1q在输入去标签、输出恢复标签；两种路径的线侧帧长均128字节。

零拷贝和单worker复制三轮均为PVID较低。双worker复制的逐轮差值为−9.35%、+13.43%、−5.62%，均值接近不足以证明统计等价或固定收益。其批量约8–10包，memif TX及公共L2节点随批量和运行时条件变化；额外采样未发现稳定的PVID专属热点，未据此增加代码。

worker采用轮询，整体CPU在两种路径均约100%，这些结果不表示整机CPU占用按表中比例下降，也不是吞吐上限。首次尝试2.0 Mpps时，发送端到被测端之间少991包；该样本没有纳入有效对照，也不宣称本轮验证了2.0 Mpps零丢包。固定256包的前述单节点结果与这里约8–14包的实际批量不能直接比较。

原生组成对照使用物理桥口、原生dot1q/dot1ad子接口及POP/PUSH。无标签入口增加VPP现有L2 classifier，拒绝落到物理桥口的未配置标签；其成本计入对照，不能拿无准入的裸桥冒充相同条件。该对照只对应本轮流量集合和非法VID拒绝，不是完整Access/Trunk/Hybrid实现。原生无标签业务按物理口计数；PVID仍额外保留业务子接口计数，没有为提速关闭统计。

10种配置的实包预检共检查5120个输出报文，标签、TPID和长度均符合预期；30个非法标签探针均未转发。60个有效性能样本累计480,288,309包，发生量、沿途收发、每个实际业务接口/子接口的包数和字节数严格匹配。混合流量按各PG流实际生成量核对两个业务，未假定绝对各半。

untag→tag三轮均较低。其余多数组合的逐轮差值跨过零，不宣称固定优势或统计等价。802.1Q双标签单worker三轮为额外3.32%–6.79%，均值5.23%，保留该测量结果。逐节点差值主要在公共memif TX；PVID的输入/输出标签处理均值反而较低。独立perf采样约7K samples/方案、丢样0，整链路差值反向，未取得可归因于PVID的稳定多余工作证据，因此没有试探性修改产品代码。

本轮仅覆盖默认零拷贝memif；转换场景的复制接收、其他Mpps、包长、物理网卡和吞吐上限未测。原始结果及CPU批量仍有波动，不能把均值视为硬件性能承诺。

## 0.30-dev 配套插件

配套 VPP 26.10.8 采用已经保留的 NAT、MQC、MSS、流量分流与 memif 优化。以下是这些优化的专项对照，不是最终安装包的整机吞吐保证。处理器为双路 Xeon E5-2670 v3，共 24 个物理核、48 个逻辑 CPU；使用 memif 和 128 字节帧，不含 FCS，也不包含物理网卡的收发成本。

| 业务组合 | 条件 | 原实现实际收包 | 优化后实际收包 | 丢包变化 |
|---|---|---:|---:|---|
| NAT | 3 workers、48 条流、目标 8 Mpps，2 次各 3 秒 | 7.086 Mpps | 7.996 Mpps | 11.395% → 0 |
| NAT＋MSS＋MQC | 3 workers、48 条流、目标 7 Mpps，2 次各 5 秒 | 6.445 Mpps | 6.999 Mpps | 7.918% → 0 |

MQC 的另一组对照每种条件运行 2 次、每次 3 秒，全部检查实际零丢包。单 worker 首项命中由 248.0 降至 231.5 packet-clocks/packet（−6.65%），末项命中由 249.0 降至 231.0（−7.23%）；3 workers、64 个键由 294.7 降至 273.7（−7.13%）。实际速率分别约 3.991、3.991 和 5.997 Mpps。packet-clocks 表示节点处理成本，不能换算为整机 CPU 占用下降比例。

单接收队列、3 workers 的多功能组合存在明确边界：1.9 Mpps 单流两次均零丢包，2.0 Mpps 单流已有少量丢包；32 条流在 2.85 Mpps 两次均零丢包，3.0 Mpps 新旧实现均未稳定零丢包。因此不将 3.0 Mpps 宣称为无损容量，也不把个别高压样本解释成普遍收益。

本版没有采用未证明稳定整链路收益的三个功能入口候选优化。上述专项结果及保留范围可查阅[配套优化记录](https://github.com/opennw-rui/VortexROS-VPP/blob/53915414622dfbc20aff09364101a9416cd6f050/docs/experiments/20261117-nat-mqc/REPORT.md)。实际容量仍应按自身帧长、流数、worker、队列、加密及策略组合验收。
