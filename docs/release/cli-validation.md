# 版本能力与限制

本页说明0.30-dev的使用范围。选择功能前，先查看[支持矩阵](../installation/support.md)和对应功能页；数据面类型、接口模式、地址族及依赖协议都会影响可用配置。

## 网络功能

| 功能 | 使用条件与检查重点 |
|---|---|
| IPv4/IPv6路由 | 先确认接口和下一跳可达，再检查路由是否进入FIB；配置存在不等于路由已生效 |
| 动态路由 | 同时检查邻居、协议路由、系统路由和业务连通；链路恢复后需等待协议重新收敛 |
| MPLS与6PE | 需要支持该功能的VPP数据面；LDP会话、标签绑定和实际转发表应一致 |
| VXLAN EVPN | VTEP底层互通，RD唯一、RT按业务匹配；配置案例分别介绍二层、三层和多归属 |
| EVPN多归属 | 支持IPv4 VTEP的All-Active；不提供Single-Active模式 |
| ACL与流量策略 | ACL为无状态permit/deny；定义后需绑定接口。NAT会话与ACL规则是不同功能 |
| DHCPv4/DHCPv6 | 客户端、服务端和中继独立配置；DHCPv6不提供默认网关，需另用RA或静态路由 |
| WireGuard/AmneziaWG | 对端公钥、Allowed IP和底层路由应匹配；建立隧道不自动发布所有站点路由 |

各案例的CE、PE、P和对端均使用VortexROS配置。SNMP管理站、SSH客户端、抓包分析器等外部应用只承担各自的应用功能，不参与案例中的设备地址或路由配置。

## 显示与检查

`display current-configuration`显示已提交配置，`display this`显示当前视图配置。协议和数据面查询用于确认运行状态；完成配置后，应从业务源地址执行`ping`或`tracert`检查实际路径。

手册中的输出是按文中拓扑整理的示例，接口名称统一为Ethernet编号。地址、计数、时长、路由数及运行标识会随设备变化，不应要求与示例逐字相同。

## 变更和恢复

`commit`提交当前会话的修改，`save`将已提交配置写入启动配置。需要重启数据面才能生效的参数，应按提示执行`reset dataplane`；协议重启和数据面重启可能中断业务。

删除对象前先解除引用。接口、底层路由或BGP进程被多个业务共用时，只撤销目标业务的绑定。安装和回退统一使用[通用安装器](../installation/07-upgrade-uninstall.md)。

## 容量与性能

配置允许的表项上限不是设备容量保证。可用内存、CPU、接口驱动、报文长度和封装层数都会影响实际承载能力。硬件选型参见[支持的硬件](../installation/hardware.md)，公开性能资料参见[性能参考](performance.md)。
