# 静态路由组

为大量前缀共用下一跳与路由属性。

[命令参考](reference/route-groups.md) · [配置案例](../examples/route-group.md)

## 工作原理与规模规划

路由组把一批目标前缀与一套共同下一跳、VPN 和路由属性关联。适合批量静态网络、地址清单或多个前缀共用同一出口；不是 BGP 的路由聚合，也不会把多个目标网络变成一个更短前缀。

前缀集合更新影响组内路由，下一跳或属性更新可能影响整个组。维护外部清单时应检查下载状态、解析结果和最终路由数量；下载成功不等于所有前缀已安装。与普通静态路由重叠时，还要比较具体前缀和优先级。

验证至少选取新增、保留和撤销的代表前缀，分别检查系统路由、FIB 和业务。撤销数据源或组时检查原来发布的路由已移除；不能只看组配置消失。
