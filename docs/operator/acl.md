# ACL

ACL 只做无状态过滤，动作只有 permit 和 deny，不建立连接表，也不根据正向放行自动放行反向报文。TCP established 是标志位匹配，不是会话状态。

## 工作原理与适用场景

ACL 逐条比较报文的地址、协议、端口和所配置的其他条件，以规则顺序决定放行或丢弃。它适合限制管理访问、隔离网段以及只允许特定应用通过；需要按用户连接分配地址时，应配置 NAT，而不是依赖 ACL。

| 需要区分的内容 | 使用含义 |
| --- | --- |
| IPv4 / IPv6 | 分别配置和绑定，IPv4 规则不能过滤 IPv6 |
| inbound / outbound | 相对于绑定接口；不是相对于业务服务器 |
| TCP established | 匹配 TCP 标志位，不证明三次握手已完成 |
| permit | 允许继续处理；后续策略、路由或接口仍可能丢弃 |

桥接端口上的二层绑定和 Vlanif 上的三层绑定覆盖不同流量。访问设备自身的报文、经过设备路由的报文、同一 VLAN 内桥接的报文，应按实际路径选择绑定位置。涉及 DHCP、ARP/ND 或路由协议时，先保留其必要流量，再收紧业务规则。未命中的处理以对应地址族和绑定方式的说明为准，不套用其他设备的缺省动作。
