# 数据面激活与恢复

修改设备模式、CPU、队列、描述符或大页等参数后，先提交、保存，再按提示激活：

~~~text
commit
save
reset dataplane
~~~

`reset dataplane`需要交互确认，可能中断由数据面承载的业务。当前远程连接经过 Vlanif 或隧道时，失败后网卡回到 Linux 并不代表这些逻辑端点也已恢复。执行切换前，应保留不依赖本次切换的恢复方式。

数据面重新激活期间会暂时恢复物理接口的 Linux 归属，再重新接管。这个临时阶段不会删除已保存的 Vlanif、DHCP 或 IPv6 业务配置；激活成功后按原配置恢复。真正切回 kernel 模式前，必须先移除仅由 VPP 提供的逻辑接口所依赖的服务，不能把临时恢复阶段当作这些功能已支持 Linux 数据面。

## 激活后检查

~~~text
display dataplane
display dataplane interfaces
display interface brief
display ip interface brief
display health
~~~

核对设备的期望模式与活动模式、接口名称、IP和路由，再从实际业务源地址执行ping。需要CPU或驱动初始化才能生效的参数，不能只根据配置显示判断已经应用。

## 仅重启当前数据面

~~~text
reset service vpp
~~~

此命令使用当前启动文件重新启动 VPP，并回放已提交配置；不会重新生成设备启动参数。Running 已配置 VPP、但上次失败已恢复到 Linux 时，该入口仍可用于修复接管，并继续使用原有接管日志和回读校验。普通配置写入限制仍保留。需要根据已保存配置重新生成启动文件时，使用 `reset dataplane`。

## 恢复默认参数

在对应视图撤销显式的worker、队列或描述符设置，提交、保存后再次激活。撤销后采用设备或驱动默认值；不同网卡的默认队列及描述符数可能不同，不应统一认定为256或1024。

切回kernel模式时保留接口的产品名称，已提交的地址和路由按新的接口归属恢复。若激活失败，先查看数据面阶段和告警，再按[管理连接恢复](../../troubleshooting/dpdk-management.md)处理。

链路重新就绪时，接口会按已提交配置恢复；DHCP 等服务暂未就绪不会阻止接口恢复。若重置后健康状态仍未恢复，先查询接口与告警，不要把命令结束等同于业务已恢复。


## 恢复顺序

恢复沿用功能依赖顺序：

1. 基础层：接口归属、VPP/LCP、VRF 和接口配置。
2. 路由层：FRR、route-zapi、静态与动态路由。
3. 业务层：DHCP、SNMP 等服务。

业务层故障必须保留明确告警和失败结果，但不阻止基础接口随链路恢复，也不能以重启正常的数据面代替业务服务恢复。升级和回退仍需核对关键组件及已配置功能的实际状态；业务未恢复时，不应将整机报告为完全正常。VortexROS 不因此新增专用管理地址或接管宿主 SSH。


正常状态下，查询结果包括：

~~~text
Foundation recovery       : ready
Routing recovery          : ready
Services recovery         : ready
~~~

三级业务故障不阻止基础接口随链路恢复。具体告警与全局未收敛状态仍保留，不能只看到 VPP 进程存在就认定业务恢复。VPP 连续启动失败受到次数限制；安装器只在明确的恢复阶段执行一次定点恢复，基础恢复失败后进入软件回退。
