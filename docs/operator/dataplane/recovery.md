# 激活与恢复

## PCI 激活与撤销的实际结果

Ubuntu 26.04.1 QEMU 的独立 virtio PCI 设备 `0000:00:02.0` 被命名为 `Ethernet0`，另一个物理接口 `eth2` 保持 Linux 模式。真实 CLI 配置主核 0、worker 1、RX/TX 各 1 队列、RX/TX 各 512 描述符，保存后激活成功。VPP 原生查询确认线程 CPU 0/1 及对应队列、描述符；接口地址恢复为 `192.0.2.65/30`，到独立虚拟对端 `192.0.2.66` 的两次探测均成功。

在同一接口在线关闭、开启 software GSO 后，能力查询的 Active 状态相应变化，恢复开启后两次探测均成功。这只证明该驱动、该参数的生效及连通性，不代表所有驱动 offload 都可在线切换，也不是吞吐测量。

撤销上述队列、描述符和 worker 设置，保存并再次激活后，原生查询只剩 main CPU 0；virtio 的 RX/TX 描述符均回到驱动默认 256，队列仍为该设备支持的 1。相同地址和对端探测继续 2/2。该 256 是本次 virtio 运行值，不是所有网卡的统一默认值。


## 冷启动端点

重启后，VPP/LCP 逻辑端点可能晚于控制服务出现。普通交换投影遇到尚未重建的端点时会记录等待，随后使用已有链路事件和已接受配置恢复；服务启动成功本身不代表对象已经全部恢复，仍需以 `display health`、接口和实际业务验证为准。存在未完成静态 MAC 补偿记录时，原恢复检查仍保留，不能把它与普通端点等待混为一谈。
