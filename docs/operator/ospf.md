# OSPF

OSPF 在同一路由域内建立 IPv4 链路状态邻接并交换前缀。创建进程不代表所有接口自动参与；选择 network 或接口激活方式，区域、网络类型、认证和计时等条件兼容后才建立邻居。

OSPFv3 用于 IPv6，见独立[OSPFv3](ospfv3.md)章节。

## 工作原理与组网选择

OSPFv2 按 RFC 2328 交换链路状态信息，各设备在区域内维护一致的链路状态数据库，再计算到目标网络的最短路径。适合一个管理域内的 IPv4 路由；不同自治系统之间的策略互联通常使用 BGP。

| 设计项 | 配置时需要明确 |
| --- | --- |
| Router ID | 在路由域内唯一且稳定，不能以邻居地址代替 |
| Area | 相连链路两端必须属于同一区域；跨区域设计围绕骨干区域 0 |
| 网络类型 | 影响邻居发现及 DR/BDR 选举，两端需兼容 |
| Cost | 影响本协议路径计算，不是系统 Preference |
| 外部路由 | 由重分发产生，E1 与 E2 的度量比较不同 |

普通广播网络中，非 DR/BDR 之间停在 2-Way 可能是正常状态；不能只以所有邻居都 Full 判断组网。先查邻居，再查 LSDB 中的类型、通告者、长度和度量，最后查系统路由及业务。默认内部优先级 10、外部优先级 150，详见[路由优先级](routing-preference.md)。

修改区域、网络类型或认证可能使邻接重新建立；重分发扩大的是路由发布范围，宜配合路由策略限制。撤销前检查是否还有其他可用路径。
