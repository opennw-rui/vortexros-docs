# DHCP

分别配置 IPv4/IPv6 服务端、客户端和中继。全局 `enable dhcp server` 只控制服务端；客户端、Relay 和 PD 按接口意图运行，不要求启用服务端。

租约中的 DNS 参数不改写 Linux 的系统解析配置。DHCPv6 不提供 IPv6 默认网关，默认路由来自 RA；不要将获取地址与获取网关混为同一步。

## 工作原理与角色选择

DHCPv4 使用地址池向客户端分配地址及网络选项；DHCPv6 按 RFC 8415 分配地址、参数或前缀。服务器保存租约，客户端请求租约，中继负责跨链路传递请求；三种角色不是一个开关的不同名称。

| 需求 | 配置角色 | 检查重点 |
| --- | --- | --- |
| 给本地终端分配地址 | Server | 地址池、网关、绑定接口和租约 |
| 设备自身从上游获取地址 | Client | 请求类型、租约及实际接口地址 |
| 客户端与服务器不在同一链路 | Relay | 服务器可达性、链路选择和返回路径 |
| 下游需要可用 IPv6 前缀 | DHCPv6 PD | 委派前缀和下游使用范围 |

空租约列表是正常状态，不是服务故障；非空租约也不等于该客户端当前在线。租约查询、接口地址、客户端路由和业务探测需分开核对。多实例使用各自的业务接口和地址池，不能因一个实例为空就忽略其他实例。

改变池、租期或 DNS 选项不保证现有客户端立即重取；应按租约更新行为检查。DHCPv6 的有状态地址、无状态参数和前缀委派分别见子页，不能将 IA_NA 的成功外推为 IA_PD 也已生效。
