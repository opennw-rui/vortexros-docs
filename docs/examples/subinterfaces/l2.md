# L2 子接口

L2 子接口按 VLAN 标签识别报文，再加入桥域转发。它自身不配置 IP；需要三层网关时，在对应 `Vbdif` 上配置地址。L3 子接口使用不同的封装命令，见 [L3 子接口](l3.md)。

## 完整案例

P1/P2 的 Ethernet0 直连。P1 以 VLAN 701 的 L2 子接口接入桥域 701，由 Vbdif701 提供网关；P2 使用相同 VLAN 的 L3 子接口。

```text
P1 Vbdif701 198.18.171.1/30
  │ bridge-domain 701
  └─ Ethernet0.701 mode l2 ── VLAN 701 ── Ethernet0.701
                                            198.18.171.2/30
```

P1：

```text
system-view
```

配置清单：

```text
enable switch
bridge-domain 701
#
interface Ethernet0.701 mode l2
 encapsulation dot1q vid 701
 bridge-domain 701
#
interface Vbdif 701
 ip address 198.18.171.1 255.255.255.252
#
```

CLI 操作：

```text
commit
```

P2：

```text
system-view
```

配置清单：

```text
interface Ethernet0.701
 vlan-type dot1q 701
 ip address 198.18.171.2 255.255.255.252
#
```

CLI 操作：

```text
commit
```

子接口编号与 VLAN 标签是两项设置，示例恰好使用相同数字。父端口上不能同时存在抢占相同标签分类的 trunk 派生成员。L2 子接口不建立独立的三层 LCP 端点，三层地址及路由属于 Vbdif；不能在这个 L2 子接口上照搬 L3 地址配置。

## 实际验证

```text
display interface Ethernet0.701
display bridge-domain 701
display mac-address bridge-domain 701
ping -c 3 -a 198.18.171.1 198.18.171.2
```

示例输出：

```text
Ethernet0.701 current state : UP
Line protocol current state : UP
Layer 2 Sub-interface, The Maximum Frame Length is 1500
Physical is 802.1Q sub-interface
Encapsulation is dot1q, VLAN 701
Bridge-domain: 701 (member)
```

```text
bridge-domain 701
  bvi: Vbdif701
  ports:
    Vbdif701         shg 0
    Ethernet0.701   shg 0
```

实际 MAC 表学习到对端 `02fe-5aef-0658`，位置为 `-/-/701`、接口为 `Ethernet0.701`、类型为 `dynamic`。MAC 随设备和测试环境而变。探测结果为 3 packets transmitted、3 received、0% packet loss。上述是功能及转发验证，不是性能结果。

## 修改、保存与撤销

确认生效后执行 `save`。修改桥域时先解除原绑定，再绑定目标桥域，并在提交后核对 MAC 学习位置及流量。

撤销本例时，两端分别删除子接口；P1 同时删除不再使用的网关和桥域：

```text
system-view
```

配置清单：

```text
undo interface Ethernet0.701
undo interface Vbdif 701
undo bridge-domain 701
```

CLI 操作：

```text
commit
```

P2：

```text
system-view
```

配置清单：

```text
undo interface Ethernet0.701
```

CLI 操作：

```text
commit
```

删除前先解除其他路由、策略或协议引用。撤销后用接口、桥域及 MAC 表查询确认对象消失；如果要在重启后保持撤销结果，再执行 `save`。

## 802.1ad 与 QinQ

两种封装应分别配置两端并检查双向业务；L2 与 L3 子接口的封装入口不同，不要混用。

### 802.1ad

P1：

```text
bridge-domain 703
#
interface Ethernet0.703 mode l2
 encapsulation dot1ad vid 703
 bridge-domain 703
#
interface Vbdif 703
 ip address 198.18.173.1 255.255.255.252
#
```

CLI 操作：

```text
commit
```

P2：

```text
bridge-domain 703
#
interface Ethernet0.703 mode l2
 encapsulation dot1ad vid 703
 bridge-domain 703
#
interface Vbdif 703
 ip address 198.18.173.2 255.255.255.252
#
```

CLI 操作：

```text
commit
```

外层标签类型为 0x88a8，不是 dot1q 的 0x8100，两端必须一致。

```text
display interface Ethernet0.703
display bridge-domain 703
ping -c 3 -a 198.18.173.1 198.18.173.2
```

接口应显示 Encapsulation is dot1ad, VLAN 703。两端 TPID、VLAN ID 和封装必须对应；提交后检查接口状态及双向探测。

### QinQ

P1：

```text
bridge-domain 704
#
interface Ethernet0.704 mode l2
 encapsulation qinq vid 704 ce-vid 70
 bridge-domain 704
#
interface Vbdif 704
 ip address 198.18.174.1 255.255.255.252
#
```

CLI 操作：

```text
commit
```

P2：

```text
bridge-domain 704
#
interface Ethernet0.704 mode l2
 encapsulation qinq vid 704 ce-vid 70
 bridge-domain 704
#
interface Vbdif 704
 ip address 198.18.174.2 255.255.255.252
#
```

CLI 操作：

```text
commit
```

此形式匹配外层 dot1q 704 与内层 dot1q 70；它与客户侧端口的[简单 QinQ](../../operator/qinq.md)是不同配置入口。

```text
display interface Ethernet0.704
display bridge-domain 704
ping -c 3 -a 198.18.174.1 198.18.174.2
```

实际桥域成员为 Vbdif704、Ethernet0.704；正向与父端口停启恢复后的探测均为 3 sent、3 received、0% packet loss。桥域入方向移除两层标签，出方向对称恢复，因此网关和其他桥域成员接收普通二层帧。

### 父接口与撤销

父接口 `shutdown` 时，单标签、802.1ad 和 QinQ 子接口及只依赖这些成员的 Vbdif 均显示 Down；保留配置。父接口 `undo shutdown` 后恢复，未将子接口自己的显式关闭配置改为开启。

撤销 703/704 案例时，P1 删除相应子接口、Vbdif 和桥域，P2 同样处理本地对象。仅删除封装会留下不完整子接口，提交校验会拒绝；要停用业务，可先 `shutdown`，要删除业务则使用 `undo interface`，不要把不完整封装当作已提交的有效配置。


两端撤销本例子接口、对应 Vbdif 和专用桥域并提交，查询接口、桥域及直连路由，确认均不再包含本例对象。其他 EVPN 业务及共享父口应保留。
