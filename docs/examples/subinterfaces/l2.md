# L2 子接口

L2 子接口按 VLAN 标签识别报文，再加入桥域转发。它自身不配置 IP；需要三层网关时，在对应 `Vbdif` 上配置地址。L3 子接口使用不同的封装命令，见 [L3 子接口](l3.md)。

## 完整案例

开发服务器的隔离 VPP 拓扑中，P1 和 P2 通过 `host-p1b12`、`host-p2b12` 互连。P1 以 VLAN 701 的 L2 子接口接入桥域 701，再由 Vbdif701 提供网关；P2 使用相同 VLAN 的 L3 子接口作为对端。

```text
P1 Vbdif701 198.18.171.1/30
  │ bridge-domain 701
  └─ host-p1b12.701 mode l2 ── VLAN 701 ── host-p2b12.701
                                            198.18.171.2/30
```

P1：

```text
system-view
enable switch
bridge-domain 701
 quit
interface host-p1b12.701 mode l2
 encapsulation dot1q vid 701
 bridge-domain 701
 quit
interface Vbdif 701
 ip address 198.18.171.1 255.255.255.252
 quit
commit
```

P2：

```text
system-view
interface host-p2b12.701
 vlan-type dot1q 701
 ip address 198.18.171.2 255.255.255.252
 quit
commit
```

子接口编号与 VLAN 标签是两项设置，示例恰好使用相同数字。父端口上不能同时存在抢占相同标签分类的 trunk 派生成员。L2 子接口不建立独立的三层 LCP 端点，三层地址及路由属于 Vbdif；不能在这个 L2 子接口上照搬 L3 地址配置。

## 实际验证

```text
display interface host-p1b12.701
display bridge-domain 701
display mac-address bridge-domain 701
ping -c 3 -a 198.18.171.1 198.18.171.2
```

实际输出节选：

```text
host-p1b12.701 current state : UP
Line protocol current state : UP
Layer 2 Sub-interface, The Maximum Frame Length is 1500
Physical is 802.1Q sub-interface
Encapsulation is dot1q, VLAN 701
Bridge-domain: 701 (member)
```

```text
bridge-domain 701
  bvi: Vbdif701
  ports:
    Vbdif701         shg 0
    host-p1b12.701   shg 0
```

实际 MAC 表学习到对端 `02fe-5aef-0658`，位置为 `-/-/701`、接口为 `host-p1b12.701`、类型为 `dynamic`。MAC 随设备和测试环境而变。探测结果为 3 packets transmitted、3 received、0% packet loss。上述是功能及转发验证，不是性能结果。

## 修改、保存与撤销

确认生效后执行 `save`。修改桥域时先解除原绑定，再绑定目标桥域，并在提交后核对 MAC 学习位置及流量。

撤销本例时，两端分别删除子接口；P1 同时删除不再使用的网关和桥域：

```text
system-view
undo interface host-p1b12.701
undo interface Vbdif 701
undo bridge-domain 701
commit
```

P2：

```text
system-view
undo interface host-p2b12.701
commit
```

删除前先解除其他路由、策略或协议引用。撤销后用接口、桥域及 MAC 表查询确认对象消失；如果要在重启后保持撤销结果，再执行 `save`。

## 802.1ad 与 QinQ

两种封装均已在同一开发拓扑中分别配置两端并验证转发，不能把 L2 的封装命令用于 L3 视图。

### 802.1ad

P1：

```text
bridge-domain 703
 quit
interface host-p1b12.703 mode l2
 encapsulation dot1ad vid 703
 bridge-domain 703
 quit
interface Vbdif 703
 ip address 198.18.173.1 255.255.255.252
 quit
commit
```

P2：

```text
bridge-domain 703
 quit
interface host-p2b12.703 mode l2
 encapsulation dot1ad vid 703
 bridge-domain 703
 quit
interface Vbdif 703
 ip address 198.18.173.2 255.255.255.252
 quit
commit
```

外层标签类型为 0x88a8，不是 dot1q 的 0x8100，两端必须一致。

```text
display interface host-p1b12.703
display bridge-domain 703
ping -c 3 -a 198.18.173.1 198.18.173.2
```

实际接口显示 `Encapsulation is dot1ad, VLAN 703`。首次成功运行有 2/3 回包；最终父接口停启后的稳定拓扑探测为 3 sent、3 received、0% packet loss。此次验证使用包含 AF_PACKET VLAN TPID 修复的配套 VPP；修复前线上为 0x88a8 的报文被接收路径错误地重建为 0x8100，导致 unknown vlan，不能以该旧失败结果宣称封装不受支持。

### QinQ

P1：

```text
bridge-domain 704
 quit
interface host-p1b12.704 mode l2
 encapsulation qinq vid 704 ce-vid 70
 bridge-domain 704
 quit
interface Vbdif 704
 ip address 198.18.174.1 255.255.255.252
 quit
commit
```

P2：

```text
bridge-domain 704
 quit
interface host-p2b12.704 mode l2
 encapsulation qinq vid 704 ce-vid 70
 bridge-domain 704
 quit
interface Vbdif 704
 ip address 198.18.174.2 255.255.255.252
 quit
commit
```

此形式匹配外层 dot1q 704 与内层 dot1q 70；它与客户侧端口的[简单 QinQ](../../operator/qinq.md)是不同配置入口。

```text
display interface host-p1b12.704
display bridge-domain 704
ping -c 3 -a 198.18.174.1 198.18.174.2
```

实际桥域成员为 Vbdif704、host-p1b12.704；正向与父端口停启恢复后的探测均为 3 sent、3 received、0% packet loss。桥域入方向移除两层标签，出方向对称恢复，因此网关和其他桥域成员接收普通二层帧。

### 父接口与撤销

父接口 `shutdown` 时，单标签、802.1ad 和 QinQ 子接口及只依赖这些成员的 Vbdif 均显示 Down；保留配置。父接口 `undo shutdown` 后恢复，未将子接口自己的显式关闭配置改为开启。

撤销 703/704 案例时，P1 删除相应子接口、Vbdif 和桥域，P2 同样处理本地对象。仅删除封装会留下不完整子接口，提交校验会拒绝；要停用业务，可先 `shutdown`，要删除业务则使用 `undo interface`，不要把不完整封装当作已提交的有效配置。


本次两端实际删除了所有实验子接口及相应 Vbdif、桥域并提交。成功的接口清单和桥域清单不再包含这些对象；Linux VLAN 清单确认两端的辅助外层均已删除，实验直连路由同时消失。P2 原有 EVPN 桥域 450 保留、健康为 ready。本例未用一次失败的查询来推断表项已经删除。
