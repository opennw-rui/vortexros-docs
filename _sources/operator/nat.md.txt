# NAT

NAT 策略按接口和方向匹配 IPv4 流量，可执行源地址转换、目的地址转换、双向转换或明确不转换。规则、地址集和地址池只定义意图，绑定接口并提交后才参与转发。NAT 需要 VPP 数据面。

先按转换方式选择子页；共享对象、回流、会话和容量分别维护。各子页给出适用条件、配置、示例输出结果和撤销步骤。

| 需求 | 功能 |
|---|---|
| 多个内部连接共享出口地址 | 接口 PAT、地址池 PAT |
| 保留源端口 | NO-PAT |
| 固定前缀的一对一转换 | 静态 NAT |
| 发布内网服务 | DNAT |
| 同时改变源、目的地址 | Twice NAT |
| 指定流量不做转换 | No-NAT |
| 内网访问发布地址 | NAT 回流 |

接口地址作为 SNAT 来源时，只能绑定 **outbound**；地址池 SNAT 的方向按业务路径选择。带端口转换的 DNAT 使用直接的目的端口匹配，不能以 port-set 替代。

配置改变主要影响新流；已有状态会话继续使用已建立的映射。验证新规则时使用新的连接，不将旧会话仍存在误判为下发失败。

## 工作原理与使用影响

NAT 按映射转换报文的地址，PAT 还转换端口，以区分共享公网地址的连接。RFC 3022 描述传统 NAT；应用是否能穿越 NAT 还取决于应用协议、连接方向和映射生命周期，不能仅按地址已改写判断应用正常。

有状态转换要求同一连接的回程经过保存其映射的设备。路径不对称、提前丢弃或会话过期都可能使回程无法还原。路由与邻居提供基础可达性，ACL 决定是否放行，NAT 不自动代替它们。静态、动态、回流和明确不转换的规则应按实际业务优先关系组织，具体匹配及绑定限制见各子页。

容量上限与活动会话数分别查询。提高容量不等于内存或吞吐无限增长；大量新连接、长超时和多个协议共享地址池时，应按设备资源规划。撤销规则后先用新连接验证，再按需要处理旧会话，避免把旧映射继续存在误认为新配置无效。
