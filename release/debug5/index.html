Debug 5

Debug 5 更新控制层，配套 VPP、FRR 和 Kea 版本与 Debug 4 相同。统一安装器只更新版本发生变化的组件，保留现有配置。更新前保存当前配置；操作步骤见升级与回退。

QinQ 服务迁移

同一父口在一次提交中迁移客户 VLAN 时，先撤销原映射，再配置目标服务，执行 commit 后按最终配置生效。双向交换、客户集合扩缩及固定外层的多内层 QinQ 使用同一规则。同一输入标签组合仍只能匹配一个服务；这项修复不放宽重叠匹配限制。

迁移会改变业务归属，可能产生短暂中断，应同时调整对端封装、地址和策略。配置、实际查询及撤销示例见灵活 QinQ。

链路聚合成员迁移

两个 Eth-Trunk 在同一次提交中交换物理成员时，聚合接口及未变化的配置保留。查询必须显示交换后的实际成员，而不能仅凭配置存在判断成功。步骤、业务影响及验证见链路聚合。

二层子接口生命周期

同一父接口下新增多个二层 QinQ 子接口时，会先完成每个子接口的二层接管，再继续创建其他子接口。修改某一子接口时，也会保留兄弟子接口各自应有的 MTU。接口归属和 MTU 以实际查询为准，配置存在并不等于提交已经完成。

修改标签归属存在短暂的转发切换窗口。最终版本的一组定向连续流量中，未修改业务与迁移业务均为200发200收，数据面没有重启；这是该组条件下的观测，不是所有组网的无损保证。

接口模式与实际查询

已存在的 VPP 物理端口，包括不使用 PCI 设备声明的接口，首次切换二层模式时会在当前提交中完成接口角色同步；返回三层模式同样按当前配置生效，不需要依赖后续再次提交。

ARP 查询与接口简表、接口详情使用相同的实际地址来源。读取接口所属路由表失败时返回查询错误，不再把无法确认的表号显示为 default。正常 IPv4/IPv6 的接口、邻居及 VPN 实例筛选语义保持。

独立救援模式重启数据面服务失败时，CLI 保留原服务错误，不会因旧数据面仍可连接而显示重启成功。

验证范围

本版以真实 CLI 验证 QinQ 迁移、正反向标签处理、保留业务、父口停启，以及 Eth-Trunk 成员交换、地址、ARP、路由和业务连通性。保存后重载配置的结果也已核对。相关缺陷另有实际 VPP 回读及失败补偿对照。仅执行本次定向验证，没有重复全量 CLI 或 CI，也不据此声明全部协议组合或转发性能已经验收。

命令参考覆盖849条规范路径；路径数量只表示文档索引范围，不等于全部参数组合均已实测。

最终安装包

最终安装文件为 vortexros_0.30-dev-debug5_amd64.run，控制层包版本为 0.30~dev+run42.debug5。QEMU 与设备升级均使用同一文件完成模拟、实际安装和健康观察；配置保持不变，配套 VPP、FRR、Kea 版本保持不变，已有后端进程保留。设备安装后的 IPv4、IPv6 和现有业务探测均通过。

本轮确认了精确回退包材料可用，没有再次执行最终包的实际反向回退。迁移流量验证不构成吞吐性能或所有切换时序无损的保证。历史 V030R-B01 特定路由解析形态与 O2-S-B3 性能异常没有新增触发证据，仍保留原有证据边界，没有以普通成功场景替代关闭依据。

完整安装结果和已知边界见 Debug 5 发布说明。
