CLI 实测记录

本页面向0.29-dev。下表复用已通过且实现未受影响的真实终端、后端及流量证据，完整步骤链接到相应案例；它不是本轮将所有功能重新执行一遍的结果。

实验采用Ubuntu26.04.1 QEMU，VPP/FRR节点使用独立网络命名空间及AF_PACKET；另有virtio PCI接口接管记录。配置和查询来自产品交互终端，流量来自实际端点或抓包。组件原生查询与产品CLI分别标注。

实际结果

预检和组件比较

Linux主实例只计划更新控制包和五个VPP包，FRR/Kea跳过；安装后同包检查返回所有版本已安装

故障自动回退

事务20261115T112610Z-106657，在validating停止route-zapi，安装器自动恢复原0.29控制包和VPP26.10.6，完成90秒观察并rolled-back；运行返回1为注入故障的预期结果

正常升级

同一.run事务20261115T113010Z-111574完成180秒连续观察并committed，返回0；Linux数据面不变、主VPP服务停止，独立原生服务保持masked

配置和身份

两次事务主启动CFG校验值均不变；dpkg文件校验干净；实际CLI、daemon、switchd和linux_nl插件哈希与包内一致；FRR主PID83256保持

无状态ACL

最终CLI分别拒绝IPv4/IPv6 permit-reflect，permit/deny可创建、显示，删除后查询对象不存在

EVPN数据面重建

保存配置后通过真实CLI reset service vpp，P1运行26.10.7、ready2/2、零告警；远端恢复双成员ES组，CE流量3/3

6PE

产品CLI建立LDP和标签邻居，Remote labels为2，实际FIB路径encap mpls2，双向各3/3

6PE撤销

二层角色和业务撤销

撤掉ESI、VNI及最后portswitch配置后，MAC/隧道0，ES成员组消失、端点流量0/3；三节点分别ready3/3、6/6、8/8、零告警，均保存成功

本轮没有重跑全量CLI、CI、未受影响的AAA/Bash、RIP及其他协议。先前控制进程冷回放、6PE已有network在线启用刷新、静态MAC与QinQ的定向证据沿用；这几项没有重标为最终包重新执行。原异常RIP进程66313仍保留供复核。

软件源码和安装包未推送GitHub、未发布软件Release或部署真机。用户手册独立提交发布。

覆盖边界

820条规范命令路径与当前Registry逐项对照。输入文本匹配只用于找遗漏，不是820个独立成功断言；各功能的创建、实际状态、流量和撤销以具体案例为准。参数取值、所有协议组合、精确竞争时序、满表规模、硬件吞吐和长期可靠性没有被穷举。

主Linux实例的包升级/自动回退与隔离VPP节点的功能恢复分别证明，不外推为真机DPDK升级验收。共享实验环境曾出现buffer耗尽及内存限额不足，这些资源前提与产品缺陷分开处理，不据此修改默认值。
