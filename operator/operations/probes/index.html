Ping、tracert 与 mtr

Ping、tracert与mtr

ping 192.0.2.1
ping -vpn-instance BLUE 10.0.0.1
tracert 198.51.100.1
mtr -vpn-instance BLUE 10.0.0.1

普通和带VPN的命令都会边执行边显示结果。Ctrl+C只中止当前诊断命令，并尽量显示已经产生的统计信息，不会关闭SSH会话。错误消息保留诊断含义，但不会暴露系统中的程序路径。

mtr在CLI中保持交互式刷新和按键控制，但用户不能借此进入Linux shell。

Ping 参数与组合

省略 -c 时发送 5 次；不写地址族时使用 IPv4。-t 是等待回复的毫秒数，-h 才是 TTL 或 IPv6 Hop Limit。常用参数可组合：

ping ip -c 2 -t 1000 -m 20 -h 17 -s 64 -tos 32 -p a1b2 -f -n -v -system-time 198.19.80.2
ping ipv6 -c 2 -t 1000 -m 20 -h 17 -s 64 -p a1b2 -n -system-time 2001:db8:80::2

在两端已有地址、路由和接口连通的情况下，上述参数组合的实际结果为各 2 发 2 收。报文的 IPv4 TTL 和 IPv6 Hop Limit 为 17，64 字节数据加上 8 字节 ICMP 头；两次请求相隔约 20 毫秒。IPv4 TOS 为 32，-f 设置 DF 位，不是高速发送模式。-p 以十六进制图案填充数据，诊断程序自身需要的时间戳字段仍可能占用载荷的开头部分。

参数

作用与注意事项

-a 地址

选择已配置的本机源地址；VPN 内的源地址应与所选 VPN 对应。

-i Ethernet0

选择发送接口；使用设备中实际存在的接口名。

-c 次数

发送次数，范围 1–1000，默认 5。

-t 毫秒

等待回复的超时时间，范围 1–60000。

-m 毫秒

请求间隔，范围 10–60000。

-h 数值

TTL／Hop Limit，范围 1–255。

-s 字节数

ICMP 数据长度，范围 0–65507；不包括 IP 和 ICMP 头。

-tos 数值

IPv4 TOS，范围 0–255；对应 IPv6 请求时为 Traffic Class。

-p 十六进制

1–16 个十六进制字符组成的填充图案。

-n

使用数字地址显示结果。

-name

允许使用主机名；名称必须能解析为所选地址族。只有 IPv4 记录的名称不能用于 ping ipv6。

-q

只保留摘要，减少逐包输出。

-system-time

在回复前显示时间戳。

-v

显示地址族、套接字和其他详细信息。

-d

请求启用套接字调试标志；不保证产生额外的逐包调试信息。

-r

IPv4 Record Route，显示沿途设备填写的选项；设备可能不处理该选项，不能代替 tracert。

-f

IPv4 设置禁止分片位；超过路径 MTU 时可能失败。

ignore-mtu

关闭路径 MTU 探测约束，允许 IPv4 分片；不应与 -f 同时用于同一次诊断。

例如，在 MTU 1500 的路径上，ping ignore-mtu -c 1 -s 1800 198.19.80.2 的实际请求被分为 1500 和 348 字节的 IP 分片，回复 1/1。这表示该路径能够完成本次分片与重组，不是提高接口 MTU，也不保证所有网络都允许分片。

-nexthop 和 -range 当前会明确返回不支持，不会发送对应的探测。不能把帮助中识别这些关键字理解为已支持下一跳查询或按长度范围自动发送。
